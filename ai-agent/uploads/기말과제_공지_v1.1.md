## 1. 과제

수업에서 만든 단어장 프로그램을 웹 앱으로 다시 만든다. 학교 서버에 올려 실행되게 하는 것까지가 과제다.

- 단어 등록, 암기, 시험, 학습 진척 통계를 만든다. 이력은 DB에 저장한다.
- AI 도구를 써도 된다. 대신 개발 방법론에 따라 문서와 코드를 함께 키운다 (docs/·CLAUDE.md·커밋 이력으로 확인).
- 결과는 GitHub 공개 리포 하나로 낸다.
- 서버에 올라간 앱은 `/2026/voca-<학번>/` 주소로 열린다.

## 2. 문서 순서

1. 공지 (이 문서)

## 4. 평가

- 기본 기능과 제출 요건을 모두 채우면 만점이다.
- 도전 기능(로그인, 다른 계정 이력 보기, 설정)은 가산점이다. 도전 기능을 했다고 빠진 기본 기능이 채워지지는 않는다.
- 평가 항목: 기능(서버 시연, 코드, DB), 문서(docs/, CLAUDE.md, 커밋 이력), 배포(서버 빌드·실행, 점검 워크플로 통과), 계정(개발 서비스 계정 관리)
- Dockerfile 필수 규칙(R-01~R-10)을 어기면 서버에 올라가지 않는다.

## 5. 꼭 지킬 것

- 리포는 공개(Public)로 한다. 비공개 리포는 받지 않는다.
- 비밀번호·키를 코드에 넣지 않는다. 환경변수로 받는다.
- DB는 SQLite를 쓴다. PostgreSQL은 11-30까지 교수에게 허락을 받아야 한다. 그 밖의 DB(MySQL 등)는 받지 않는다.
- 리포 루트에 Dockerfile과 `.github/workflows/docker-check.yml`을 둔다.
- README.md에 앱 소개, 실행 방법, 구현한 요구사항 ID, 고른 DB를 적는다.

## 6. 제출 방법

제출 폼은 학교 계정으로 로그인해야 보인다.

| 항목 | 적는 법 |
|------|---------|
| GitHub 리포 URL | `https://github.com/<아이디>/<리포>` |
| 제출 커밋 | 커밋 SHA 40자. 점검 워크플로가 초록(통과)인 커밋 |
| 앱 이름 | 30자 이내 |
| 한 줄 설명 | 80자 이내. 실명·학번 금지 |
| 공개 리포 확인 | 시크릿 창에서 리포 주소가 열리는지 확인 후 체크 |
| 계정 자가 신고 | 「소프트웨어 요건」 §4.5의 두 항목 |

- 서버 주소는 `/2026/voca-<학번>/`으로 자동 지정된다.
- 고친 뒤에는 새 커밋 SHA로 폼을 다시 저장한다. 폼에 적힌 커밋이 평가 대상이다.
- 평가가 끝날 때까지 리포를 지우거나 비공개로 바꾸거나 force-push하지 않는다.

## 2. 기능 요구사항 (VOCA-FR)

### 2.1 단어 등록 — 기본

| ID | 요구사항 | 확인 |
|----|----------|------|
| VOCA-FR-001 | 영단어와 뜻을 직접 입력해 등록한다 | 시연 |
| VOCA-FR-002 | 등록된 단어를 목록으로 보고, 수정·삭제한다 | 시연 |
| VOCA-FR-003 | 제공 CSV(영단어,뜻, 2,000개)를 가져와 일괄 등록한다. 중복 처리 방침은 직접 정하고 문서에 적는다 | 시연·코드 |
| VOCA-FR-004 | 단어를 검색한다 (영단어 또는 뜻) | 시연 |

| 조건 | 내 앱에 필요한 것 |
|------|------------------|
| 포트 8080으로 요청이 들어온다 | 0.0.0.0:8080에서 듣는다 (localhost·127.0.0.1 안 됨) |
| 주소 `/2026/voca-<학번>/` 아래에서 열린다 | 앱은 `/` 기준. 서버가 주소 앞부분을 떼고 넘긴다 |
| UID 10001, 리눅스 권한 없이 실행 | 실행 중 root 권한이 필요한 일을 하지 않는다 |
| 쓰기는 /data·/tmp에만 된다 | SQLite 파일은 `/data/voca.db` |
| 실행 중 인터넷이 막혀 있다 | 의존성은 빌드할 때 모두 설치 |
| 비밀값은 환경변수로 준다 | SECRET_KEY, DB 접속 정보 |
| 메모리는 1GB까지 | 보통의 웹 앱이면 충분 |

## 2. 리포에 둘 파일

- `Dockerfile` (필수), `.dockerignore` (권장), `.gitattributes` (권장)
- `.github/workflows/docker-check.yml` (필수, 고치지 않고 넣음)
- `README.md`, `CLAUDE.md`, `docs/`, 앱 코드

## 3. 규칙

### 3.1 필수 (어기면 서버에 올라가지 않음)

| ID | 규칙 |
|----|------|
| R-01 | 리포 루트에 Dockerfile이 있고, 루트에서 `docker build .` 한 번으로 이미지가 만들어진다 |
| R-02 | 공식 이미지에서 시작하고 버전 태그를 적는다 (`python:3.13-slim` ○, `python` ×, `latest` ×) |
| R-03 | 앱은 0.0.0.0:8080에서 듣는다 |
| R-04 | 앱은 `/` 기준. ① 주소는 `/login`처럼 `/`로 시작하거나 `login`처럼 상대 경로. ② HTML 속성은 따옴표로 감싼다 (`href="/login"` ○, `href=/login` ×). ③ JS는 `fetch("/api/words")`처럼 호출 자리에 문자열로 쓴다 (`const API = "/api"` 같은 변수 분리 금지). ④ `http://localhost:8080` 같은 호스트를 코드에 쓰지 않는다. ⑤ 주소를 JSON 응답에 담아 내려 주지 않는다 |
| R-05 | UID 10001로 실행해도 동작한다. Dockerfile에서 UID 10001 사용자를 만들고 마지막 USER로 지정한다. 실행 중 chown, 패키지 설치, 1024 미만 포트 같은 root 작업 금지 |
| R-06 | DB는 SQLite. 위치는 환경변수 `DB_PATH`(값 `/data/voca.db`)를 따른다. Dockerfile에서 /data를 만들고 소유자를 10001로 한다. 처음 실행하면 테이블을 스스로 만든다. 실행 중 파일 쓰기는 /data와 /tmp에만 |
| R-07 | 실행 중 인터넷이 필요 없다. 의존성은 빌드할 때 설치 |
| R-08 | 비밀값을 리포·이미지에 넣지 않는다. 세션 키는 `SECRET_KEY` 환경변수, 없으면 기동할 때 무작위 생성. `.env`는 커밋하지 않는다 |
| R-09 | 점검 워크플로를 고치지 않고 넣고, 제출 커밋에서 통과(초록) |
| R-10 | 서버 빌드에서 거부되는 지시 금지: 첫 줄 `# syntax=` 지시어, `RUN --mount=type=ssh`·`RUN --mount=type=secret`, `RUN --network=…`, `RUN --security=…` |

### 3.2 권장 (어기면 감점)

| ID | 규칙 |
|----|------|
| R-11 | `.dockerignore`로 .git, .venv·venv, node_modules, __pycache__, *.db, .env, IDE 설정을 뺀다 |
| R-12 | `.gitattributes`에 `* text=auto eol=lf` |
| R-13 | 의존성 파일을 소스보다 먼저 COPY해서 설치 (Python은 requirements.txt) |
| R-14 | 운영용 서버로 띄운다 (Flask → gunicorn). `flask run`, `--reload`, `debug=True` 금지 |
| R-15 | CMD는 exec 형식 `["…", "…"]` |
| R-16 | 이미지 크기 500MB 이하 |

### 3.3 하지 않아도 되는 것

하위 경로(`/2026/voca-<학번>/`)에 맞추는 코드, docker-compose.yml, HTTPS, 도메인, 포트 공개.

## 4. 점검 워크플로로 확인하기

Docker를 내 PC에 설치하지 않아도 된다. GitHub가 서버와 같은 조건으로 빌드하고 띄워 본다.

- 넣는 법: `.github/workflows/` 폴더에 넣고 커밋·푸시. 내용은 고치지 않는다.
- 결과: GitHub 리포의 Actions 탭. 초록 체크면 통과, 빨간 X면 실패. 실패 단계의 "실패하면 앱 로그"에 앱 오류가 나온다.

| 단계 | 하는 일 | 실패하면 |
|------|---------|----------|
| 0 | Dockerfile 문법 점검 (참고용) | 실패로 치지 않음. 경고는 R-02·R-15 확인에 씀 |
| 1 | 빌드 | Dockerfile·의존성 파일 수정 (R-01·R-02·R-10) |
| 2 | 서버 환경 준비 | — |
| 3 | 서버 조건으로 앱 실행 | R-05·R-06 |
| 4 | 30초 안에 첫 화면 응답 | R-03, 시작 오류 |
| 5 | 첫 화면 링크 점검 (FAIL은 앱 밖을 가리킴) | R-04 |
| 6 | 재시작 후 응답, /data 파일 확인 | R-06 |
| 7 | 이미지 크기 표시 | R-16 |

제출 폼에는 Actions가 초록인 커밋의 SHA를 적는다.
