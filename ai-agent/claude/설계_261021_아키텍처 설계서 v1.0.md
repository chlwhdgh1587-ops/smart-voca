## 1. 개요

- 개인용 객관식 영어 단어 암기 웹 앱을 교실 PC에서 로컬로 실행한다.
- 기술 선택과 근거는 결정 기록(ADR-001~004)에 있다.

---

## 2. 구성 요소 (Topology)

```
[브라우저 (교실 PC)]
        │  HTTP (127.0.0.1:5000)
        ▼
[Flask 앱 (로컬 프로세스, python src/app.py)]
        │  sqlite3 (표준 라이브러리)
        ▼
[SQLite 파일 data/smartvoca.db]
```

| 구성 요소 | 역할 | 비고 |
|-----------|------|------|
| 브라우저 | 화면 표시, 답안 입력 | 별도 설치 없음 |
| Flask 앱 | 라우팅, 학습 로직 호출, HTML 렌더링 | 외부 통신 없음 |
| SQLite | 단어와 학습 상태, 기록 저장 | NFR-02 보존 |

외부 서버, 클라우드, 인터넷 연결은 사용하지 않는다 (NFR-03, ADR-002).

---

## 3. 디렉토리 구조

```
smart-voca/
├── src/
│   ├── app.py                  # Flask 진입점, 라우트 정의 (FR 전체 연결)
│   ├── db.py                   # DB 연결, 테이블 생성 (데이터 설계서)
│   ├── word_service.py         # 단어 등록·수정·삭제·목록 (FR-01)
│   ├── study_service.py        # 세션 구성, 출제, 답안 처리, 복습 해제 (FR-02, FR-03)
│   ├── report_service.py       # 학습 기록 집계 (FR-04)
│   ├── seed_words.py           # 기초 단어 목록 1회 적재 (NFR-05)
│   ├── templates/              # HTML 화면 (UI 설계서)
│   └── static/style.css        # 화면 스타일
├── data/
│   ├── smartvoca.db            # 실행 시 생성 (gitignore 대상)
│   └── words_public.csv        # 직접 작성한 기초 영단어 100개 (NFR-05)
└── requirements.txt            # Flask 버전 고정
```

- 한 파일이 500줄을 넘으면 분리를 제안한다 (CLAUDE.md 개발 원칙 5).
- 모든 파일 최상단에 CLAUDE.md의 헤더(작성일, 파일 위치, 목적)를 둔다.

## 5. HTTP 인터페이스

| 메서드 | 경로 | 요청 | 응답 | 연결 기능 |
|--------|------|------|------|-----------|
| GET | `/` | 없음 | 홈 화면 (복습 수, 오늘 신규 남은 수) | 전체 |
| GET | `/study` | 없음 | 학습 화면 (현재 문제). 진행 중인 세션이 없으면 새로 구성하고, 있으면 이어서 출제 | FR-02, FR-03 |
| POST | `/api/study/answer` | `word_id`, `selected_meaning` | `{correct, correct_meaning, session_finished, session_id}` JSON | FR-02.3, FR-02.4 |
| GET | `/study/done` | 없음 | 세션 완료 화면 | FR-04.2 |
| GET | `/words` | 없음 | 단어 목록 및 등록 폼 | FR-01.4 |
| POST | `/words` | `english`, `meaning`, `example`(선택) | 목록으로 redirect | FR-01.1 |
| POST | `/words/<id>/edit` | `english`, `meaning`, `example` | 목록으로 redirect | FR-01.2 |
| POST | `/words/<id>/delete` | 없음 | 목록으로 redirect | FR-01.3 |
| GET | `/report` | 없음 | 기록 화면 | FR-04.1~04.3 |

- 답안 제출만 JSON으로 주고받아 피드백을 즉시 표시한다 (NFR-01). 나머지는 폼 POST와 redirect를 쓴다.
- 서버는 `127.0.0.1`에만 바인딩한다 (외부 접속 차단).

**세션 상태 관리**
- 진행 중인 세션의 출제 목록과 재시험 큐는 서버 메모리(`study_service`의 모듈 상태)에 둔다. 단일 사용자, 단일 프로세스 가정이다.
- 학습 결과(연속 정답 수, 복습 대상, 답안 기록)는 항상 DB에 바로 저장한다 (NFR-02).
- 앱을 재시작하면 메모리 상태는 사라진다. 다음 `/study` 접속 때 `finished_at`이 비어 있는 이전 세션을 현재 시각으로 종료 처리하고 새 세션을 구성한다 (프로세스 설계서 1절).

## 6. 비기능 요구 대응

| NFR | 대응 방식 |
|-----|-----------|
| NFR-01 사용성 | 답안 제출을 JSON으로 처리해 피드백을 1초 이내 표시. 큰 글자와 버튼 (UI 설계서) |
| NFR-02 데이터 보존 | 모든 학습 상태를 SQLite에 저장. 재실행 시 그대로 복원 |
| NFR-03 개인정보 | 실명, 학번 필드 없음. 외부 전송 없음 |
| NFR-04 추적성 | 각 함수 주석과 테스트 이름에 FR ID 명시 |
| NFR-05 초기 데이터 | `seed_words.py`가 `words_public.csv`를 1회 적재 |

---

## 7. 실행 방식 (요약)

1. `pip install -r requirements.txt` (Flask 설치, 승인 후 수행)
2. `python src/seed_words.py` (기초 단어 100개 적재, 1회)
3. `python src/app.py` 실행 후 브라우저에서 `http://127.0.0.1:5000` 접속

상세 실행 절차는 구현 단계에서 README와 CLAUDE.md 테스트 섹션에 기록한다.
